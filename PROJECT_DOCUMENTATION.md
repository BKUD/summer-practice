# Проект `ontol_v3_students`: UML DSL с TDL и Graphviz

## 1. Обзор проекта

`ontol_v3_students` — система для текстового описания, генерации, проверки и обратного восстановления UML-диаграмм классов.

В проект входят:

- **TDL (Text Diagram Language)** — русскоязычный предметно-ориентированный язык описания UML-диаграмм классов;
- **Pydantic-модель UML** — типизированное представление классов, атрибутов, операций и отношений;
- **Graphviz-рендеринг** — автоматическая генерация DOT и SVG через системную команду `dot`;
- **семантические SVG-метаданные** — `data-*` атрибуты для обратного разбора;
- **обратный парсинг SVG** — восстановление Pydantic-модели из SVG;
- **сериализация обратно в TDL**;
- **Streamlit-интерфейс** для генерации и проверки диаграмм;
- **экспорт в PNG и JPG**;
- **автоматические тесты** полного конвейера.

**Технологии:** Python 3.10+, Pydantic v2, Graphviz, Streamlit, CairoSVG, Pillow, pytest.

---

## 2. Цель работы

Цель проекта — создать воспроизводимый конвейер, в котором UML-диаграмма задаётся как текст, автоматически визуализируется и может быть восстановлена обратно без потери основной семантики.

Основной конвейер:

```text
TDL
→ лексер
→ парсер
→ AST
→ Pydantic-модель
→ DOT
→ Graphviz
→ SVG с data-атрибутами
→ Pydantic-модель
→ TDL
```

### Основные требования

- детерминированная генерация SVG;
- автоматическая раскладка классов и связей;
- строгая типизация UML-модели;
- семантическая валидация;
- сохранение ролей, кратностей, агрегации и композиции;
- сохранение TDL-команд размещения;
- совместимость с ранее созданными SVG;
- работа через CLI и веб-интерфейс;
- экспорт в SVG, PNG и JPG.


## 4. Структура модулей

### `models.py`

Базовые UML-модели:

- `Class`;
- `Attribute`;
- `Operation`;
- `Parameter`;
- `MultiplicityRange`;
- другие классификаторы и элементы модели.

### `relationships.py`

Отношения между классификаторами:

- `Association`;
- `AssociationEnd`;
- `Dependency`;
- `Generalization`;
- `Realization`.

Ассоциации поддерживают:

- роли;
- кратности;
- навигацию;
- агрегацию;
- композицию;
- имя отношения;
- признак производности.

### `enums.py`

Перечисления предметной модели:

- видимость;
- стереотипы;
- типы агрегации;
- другие UML-параметры.

### `diagram.py`

Контейнер диаграммы `ClassDiagram`.

Хранит:

- классификаторы;
- ассоциации;
- зависимости;
- обобщения;
- реализации;
- позиции;
- нормализованные команды размещения `layout_commands`.

Также выполняет глобальную семантическую валидацию.

### `tdl_lexer.py`

Преобразует исходный текст TDL в последовательность токенов.

Поддерживает:

- ключевые слова;
- идентификаторы;
- числа;
- строки;
- символы видимости;
- диапазоны кратности;
- комментарии;
- команды размещения;
- ключевые слова агрегации и композиции.

Основная функция:

```python
lex(source: str)
```

### `tdl_parser.py`

Преобразует токены в AST.

Основная функция:

```python
parse_tdl(tokens)
```

Парсер обрабатывает:

- классы;
- атрибуты;
- операции;
- параметры;
- ассоциации;
- зависимости;
- обобщения;
- реализации;
- блоки размещения.

### `tdl_ast.py`

Содержит классы абстрактного синтаксического дерева TDL.

AST отделяет синтаксис языка от Pydantic-модели UML.

### `tdl_build.py`

Преобразует AST в `ClassDiagram`.

Основная функция:

```python
build_diagram(document)
```

На этом этапе:

- разрешаются ссылки между классами;
- создаются отношения;
- разбираются кратности;
- назначаются типы агрегации;
- нормализуются команды размещения;
- выполняются проверки модели.

### `graphviz_render.py`

Генерация DOT и SVG.

Основные функции:

```python
diagram_to_dot(diagram)
diagram_to_graphviz_svg(diagram)
enrich_svg_with_data_attrs(svg_text, diagram, node_map)
```

Задачи модуля:

1. преобразовать Pydantic-модель в DOT;
2. вызвать системную команду `dot`;
3. получить SVG;
4. добавить семантические `data-*` атрибуты;
5. сохранить метаданные версии и размещения.

Для UML-классов используются HTML-подобные TABLE-метки Graphviz, благодаря чему атрибуты и операции отображаются в отдельных секциях.

### `svg_metadata.py`

Централизованные константы SVG-метаданных:

- `data-tdl-schema`;
- `data-layout`;
- текущая версия схемы;
- поддерживаемые версии;
- legacy-версия.

Текущая версия метаданных:

```text
data-tdl-schema="1"
```

### `svg_parser.py`

Обратный разбор SVG.

Основная функция:

```python
parse_svg_to_diagram(svg_content: str) -> ParseResult
```

Парсер:

- проверяет XML;
- определяет версию SVG-метаданных;
- поддерживает legacy SVG без `data-tdl-schema`;
- восстанавливает `layout_commands`;
- читает классы из `data-model`;
- восстанавливает отношения из `data-*`;
- собирает ошибки и предупреждения;
- возвращает `success=False`, если есть ошибки.

### `tdl_serializer.py`

Обратная сериализация Pydantic-модели в TDL.

Основная функция:

```python
diagram_to_tdl(diagram: ClassDiagram) -> str
```

Сериализатор поддерживает:

- классы;
- атрибуты;
- операции;
- обобщения;
- зависимости;
- реализации;
- бинарные ассоциации;
- роли;
- кратности;
- агрегацию;
- композицию;
- команды размещения.

### `tdl_run.py`

Публичный программный API и CLI.

Основные функции:

```python
tdl_to_svg(tdl_source: str) -> str
render_tdl_file(input_path: Path, output_path: Path) -> Path
main(argv=None) -> int
```

`tdl_to_svg()` используется Streamlit-приложением.

`render_tdl_file()`:

- читает `.tdl`;
- генерирует SVG;
- создаёт родительский каталог результата;
- сохраняет файл.

### `app.py`

Streamlit-приложение с двумя вкладками:

1. **Валидатор SVG**
   - загрузка SVG;
   - обратный парсинг;
   - вывод ошибок и предупреждений;
   - семантическая валидация;
   - статистика модели;
   - превью.

2. **Рендер TDL**
   - ввод или загрузка TDL;
   - генерация SVG;
   - превью;
   - скачивание SVG;
   - экспорт PNG/JPG.

SVG-превью выводится как Base64-изображение, чтобы стили Streamlit не нарушали разметку Graphviz.

### `export.py`

Экспорт SVG в растровые форматы:

- PNG через CairoSVG;
- JPG через CairoSVG и Pillow.

## 6. Команды размещения TDL

Диаграмма может содержать блок:

```tdl
РАЗМЕЩЕНИЕ
  РАСПРЕДЕЛИТЬ ПО ГОРИЗОНТАЛИ A B C ШАГ 10
  ПРИВЯЗАТЬ D ЛЕВЕЕ A
  ПРИВЯЗАТЬ E ВЫШЕ D
КОНЕЦ РАЗМЕЩЕНИЕ
```

Поддерживаемые команды:

- выравнивание;
- распределение по горизонтали;
- распределение по вертикали;
- привязка левее/правее;
- привязка выше/ниже;
- фиксация координат.

Команды преобразуются в ограничения DOT:

- `rank=same`;
- невидимые рёбра;
- порядок узлов;
- весовые ограничения;
- позиционные метаданные.

Graphviz выполняет финальную автоматическую раскладку, поэтому команды размещения являются декларативными ограничениями, а не прямым рисованием координат.

## 7. SVG-метаданные

После рендеринга Graphviz SVG обогащается атрибутами.

### Корневой элемент

```xml
<svg
  data-tdl-schema="1"
  data-layout="[...]">
```

### Класс

```xml
<g
  data-type="class"
  data-id="C0"
  data-name="РоботБиолог"
  data-model="{...}">
```

`data-model` содержит JSON-представление Pydantic-модели класса.

### Ассоциация

Используются:

```text
data-type
data-src
data-tgt
data-name
data-derived
data-src-role
data-tgt-role
data-src-multiplicity
data-tgt-multiplicity
data-src-aggregation
data-tgt-aggregation
data-src-navigable
data-tgt-navigable
```

### Версионирование

- версия `0` — legacy SVG без явного `data-tdl-schema`;
- версия `1` — текущая схема с `data-layout`;
- неподдерживаемая или некорректная версия считается ошибкой;
- отсутствие `data-layout` в текущей версии создаёт предупреждение, но не блокирует разбор;
- старые SVG без `data-layout` поддерживаются в режиме совместимости.

## 9. Установка

### 9.1. Требования

- Python 3.10 или новее;
- системный Graphviz;
- команда `dot` должна быть доступна через `PATH`.

Проверка Graphviz:

```powershell
dot -V
Get-Command dot
```

Проект вызывает `dot` напрямую через `subprocess`. Python-пакет `graphviz` не требуется.

### 9.2. Виртуальное окружение

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Если PowerShell блокирует активацию:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

### 9.3. Зависимости для разработки

```powershell
python -m pip install -r requirements-dev.txt
```

`requirements-dev.txt` подключает runtime-зависимости и устанавливает pytest.

## 10. Использование

### 10.1. CLI: TDL → SVG

```powershell
python -m uml_dsl.tdl_run `
  .\examples\robot_biologist.tdl `
  -o .\output\robot.svg
```

Параметр `-o` / `--output` обязателен и задаёт путь сохранения.

При необходимости родительский каталог создаётся автоматически.

### 10.2. Программный API

```python
from uml_dsl.tdl_run import tdl_to_svg

source = """
КЛАСС Пример
КОНЕЦ КЛАСС
"""

svg = tdl_to_svg(source)
```

### 10.3. Streamlit

```powershell
python -m streamlit run uml_dsl/app.py
```

Обычно приложение становится доступно по адресу:

```text
http://localhost:8501
```

## 13. Известные ограничения

- основной тип диаграммы — UML-диаграмма классов;
- автоматическая раскладка зависит от возможностей Graphviz;
- команды размещения задают ограничения, но не гарантируют пиксельные координаты;
- обратная сериализация ориентирована на поддерживаемое подмножество TDL;
- сложные N-арные ассоциации могут требовать отдельного расширения сериализатора;
- интерактивное drag-and-drop редактирование не является частью текущего решения;
- SVG без семантических `data-*` атрибутов невозможно полностью восстановить в UML-модель.
